# 验收说明

版本：`1.0.0`。模拟测试与真实平台验收分开记录：前者不能证明学习通页面、平台回执或真实 AI 调用已经通过。1.0.0 由用户要求先开发发布、再由用户实机测试；正式版不等于真实验收通过。

## 模拟与工程验证

执行 `npm run check`，依次运行 TypeScript 检查、单元测试、构建及 Playwright 模拟页面回放。测试使用本地模拟页面及模拟 AI 接口，不访问真实课程或发送真实 AI 请求。完成结果见命令输出及本机 `test-results/results.json`。

2026-10-29：1.0.0 的类型检查、61 项单元测试和 45 项模拟页面测试通过。新增「所有标签页都保留服务商背景和主题配色」回归；课程、播放、运行、AI 设置、复习五个标签页均验证背景图、主题属性与半透明内容层。另用本机截图人工检查了 Kimi 主题五页和 360×640 窄屏布局，未发现文字溢出或面板越界。

2026-10-28：0.5.8 候选版的类型检查、61 项单元测试和 44 项模拟页面测试通过，新增父页面任务身份缺失超时、目标章节未标记完成但仍切换、间歇暂停恢复场景。真实平台后台验收仍待验证。

2026-10-28：0.5.7 候选版的类型检查、61 项单元测试和 43 项模拟页面测试通过，新增播放器启动未成功和间歇暂停后恢复场景。

2026-10-28：0.5.6 类型检查、61 项单元测试和 41 项模拟页面测试通过；新增跨域播放器任务身份、同章节多视频、连续章节、媒体源延迟和打开失败不跳章等场景。

2026-10-28：0.5.5 的类型检查与构建通过，61 项单元测试和 36 项模拟页面测试通过，包含主页入口、章节链接、空音频过滤、两个视频顺序播放及跨域卡片页自动打开回归。0.5.4 修正了“视频已到结尾但本地观看时长记录不足”导致的卡住问题，改为结合浏览器 `played` 区间、恢复位置和平台回执判断；0.5.5 修正了该版本将“任务点未完成”误判为已完成、从而跳过播放的回归。

验证范围包括常见题型、图片题、讨论去重、复习资料、考试人工交卷、嵌套 iframe、课程切换、跨标签页协调、媒体播放、效率要求、平台回执、AI 调用范围、密钥保护，以及四种主题切换和窄窗口布局。

三个角色背景内嵌脚本；五个标签页都保留角色背景与当前服务商配色，模型或服务商切换可触发入场动画，系统要求减少动态效果时停用。自定义接口使用中性背景。背景与动画由本地样例页面和截图验证，真实学习通页面尚未验证。

效率模式要求实际记录的观看量满足明确条件，再依据平台回执确认；条件未知时完整播放。平台提前返回通过不能代替观看要求，原有自动拖动设置已停用。实际观看量记录不足时会保留待办，不应将到达视频结尾等同于完整观看。

考试确认前提交请求应为零，确认仅对当前考试、本次提交有效；刷新和重试不得继承。模拟结果不能保证平台所有考试页面或变体都已适配。

## 真实平台验收

2026-10-28：在已授权课程的 0.5.5 运行页面观察到，脚本播放了目录显示已完成的章节视频，运行列表还保留其他章节的旧等待项；随后自动进入另一章节，但其中视频停在 0:00。0.5.6 增加跨域任务身份识别和导航响应确认；模拟结果不能代替真实验收。

同日安装 0.5.6 后，在已授权课程中将正在播放的标签页切到后台超过五分钟：面板记录从 278 / 1830 秒推进到 310 / 1830 秒，随后显示“媒体多次暂停或卡顿”。该次后台验收失败；不能据此推断连续播放或平台任务点完成。0.5.7 修复暂停恢复后的计数和错误分类，仍需真实课程重新验收。

用户随后确认安装 0.5.7 测试候选版，并反馈“依旧不行”。该反馈尚无对应的独立日志和详细复现记录，根因及候选版后台表现均未确认。

1.0.0 是按用户要求“直接开发并发布、由用户实机测试”生成的正式版；**代码层面只新增了全标签页主题 UI 和版本/文档，没有改变 0.5.8 的播放调度逻辑**。因此 1.0.0 发布不等于真实平台验收通过；真实验收必须以用户明天测试后的日志为准。

0.5.8 针对可静态确认的两个阻塞点做了修复：父页面未回应任务/考试上下文时，子播放器过去会无限等待而停在 0:00；现在 5 秒后按自身页面信息继续。章节任务全部通过但平台未显示完成图标时，过去会一直停在“等待平台确认当前章节完成”；现在只要已加载任务均通过或没有必做任务就允许切换。后台暂停也改为记录媒体状态并耐心重试，10 分钟无进度才转人工。真实效果仍需用户实测。

用户曾反馈旧版本已经播放并完成一个任务点。真实页面复现 0.5.0 主页启动后“无效的参数”；0.5.1 已实测从主页成功进入所选课程的章节，但未确认视频自动播放，且运行页打开脱敏章节地址时复现 `enc校验失败`。0.5.2 修复了任务页校验和无源音频识别。用户反馈完成一个视频后不会自动切换；0.5.3 修复待处理任务过滤并增加同章节/跨域卡片页自动打开任务点。

用户随后提供了真实运行日志：`走近马克思主义基本原理1.mp4：视频已到结尾，但已记录的观看时长不足；保留待办`，任务显示 `580 / 580 秒`、状态“等待运行”。说明视频实际已到结尾，但本地 `watched` 计数低于时长，队列因此反复保留待办，也无法继续下一个视频。0.5.4 改为用浏览器 `played` 时间区间、恢复位置和平台回执共同判断，并在播放前先核验平台是否已完成。

用户更新 0.5.4 后反馈“无法自动播放”。排查发现 0.5.4 新增的任务点 DOM 判断把 `aria-label="任务点未完成"` 中的“完成”误判为已通过，导致视频被跳过并直接标记完成。0.5.5 已排除“未完成/未通过”等否定标签，并在模拟页面中加入真实属性回归；真实效果仍需更新后确认。

用户已表示接入 DeepSeek API，但本仓库测试不读取用户密钥，也未向真实 DeepSeek 发送请求；真实文本题、图片题、讨论、复习总结与失败处理仍需在非关键任务中验收。真实 AI 调用、任务点切换和五分钟后台观察都不得以模拟结果代替。

用户回来后，在已选课程中完成以下检查：

1. 安装本地构建的脚本并先检查现有状态，避免重复提交或覆盖用户进度。
2. 记录课程章节、播放进度、平台任务点状态和 AI 调用次数。将课程标签页切到后台，保持浏览器与电脑运行至少五分钟，再记录进度和平台状态；浏览器冻结或系统休眠时不得判为通过。
3. 在适用的非关键任务中验证题目、讨论、文档、效率条件和平台回执；存在未解决题目或平台回执不明时不得当作成功。
4. 用户在油猴设置中自行填写 AI Key，不向聊天、日志或截图提供密钥。按实际可用服务验证文本和图片题、总结与失败处理。
5. 考试仅由用户主动开始，交卷仅由用户确认；真实页面的确认前零请求和刷新后不继承授权仍需核验。
